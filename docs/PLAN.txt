4.1 Parsing
PDF/DOCX/PPTX sab ke andar text alag tareeke se store hota hai. Parser ka kaam ek hi hai:
kisi bhi format se plain text nikalna. pypdf  PDF pages se, python-docx  paragraphs se,
python-pptx  har slide ke text frames se. Limitation: scanned PDF (image) mein text nahi
hota, uske liye OCR chahiye. Hum us case ko saaf error dete hain, OCR scope se bahar hai.
4.2 Chunking
LLM ko poora document nahi de sakte (context limit, slow, quality girti hai). Toh text ko
chunks mein todte hain, ~800 characters, paragraph boundary pe. Overlap (100 chars)
isliye ki ek idea do chunks ke beech kat na jaye. Chhota chunk = precise par context kam.
Bada chunk = context zyada par noisy. 500 se 1000 chars ek achha start hai.
4.3 Quiz generation retrieval nahi hai
RAG mein sawal aata hai aur hum uske jawab ke chunks dhundhte hain. Quiz mein koi
sawal nahi hota, poora document cover karna hota hai. Isliye default mode mein hum
chunks ko document mein barabar doori pe sample karte hain ( pick_spread ) aur har
chunk se ek MCQ banate hain. Retrieval tab kaam aata hai jab user bole "sirf
photosynthesis pe quiz" (topic mode).

4.4 Hybrid search + rerank (topic mode)
Dense (embeddings + FAISS): all-MiniLM-L6-v2  har chunk ko 384-number ke vector
mein badalta hai. Matlab pakadta hai, exact words nahi. "car" aur "automobile" paas
aate hain.
Sparse (BM25): keyword matching. Rare words aur exact terms (naam, acronyms)
mein dense se behtar.
Fusion (RRF, Reciprocal Rank Fusion): dono ki ranked lists ko score 1 / (60 + rank)
se jodte hain. Jo chunk dono mein upar ho wo jeetta hai. Scores alag scale ke hote hain,
isliye rank use karte hain, score nahi.
Rerank (cross-encoder): top ~15 candidates ko ms-marco-MiniLM  ke saath (query,
chunk) joda banake dobara score karte hain. Ye slow par accurate hai, isliye sirf
shortlist pe chalate hain. Pattern: fast retrieval se shortlist, slow reranker se final.
4.5 LLM se structured output
Ollama mein format: "json"  dene se output valid JSON hone ki koshish karta hai. Phir
bhi galat keys, 3 options, ya answer_index 9 aa sakta hai. LLM ka output untrusted input
hai, user input ki tarah. Isliye validate karte hain. temperature  0.3 rakhte hain taaki
output stable rahe.
4.6 Validation: schema + grounding
1. Schema (Pydantic): question string, exactly 4 distinct options, answer_index  0 se 3.
2. Grounding: LLM ko bolte hain ki jawab ka saboot ek exact sentence source_snippet
mein copy kare. Hum check karte hain ki wo sentence chunk mein sach mein hai. Nahi
hai toh question reject.
Honest limitation: grounding ye prove karta hai ki LLM ne source se quote kiya, ye nahi ki
answer_index  sahi option pe hai. Isliye demo cache haath se review hota hai. Viva mein
ye limitation khud bolna achha impression deta hai.
4.7 Cache by content hash
SHA-256 file ke bytes ka fingerprint hai. Same file = same hash, ek bhi byte badla toh alag.
Isliye cache sirf asli demo file pe lagta hai, kisi aur document pe nahi.
4.8 Security: LLM output ko UI mein daalna
LLM ka text innerHTML  mein daalna XSS hai. Hum frontend mein textContent  use karte
hain, jo text ko text hi rakhta hai.

def parse_file(path: str) -> str:
    ext = Path(path).suffix.lower()
    if ext not in PARSERS:
        raise ValueError(f"Unsupported file type: {ext}")
    text = PARSERS[ext](path)
    if not text.strip():
        raise ValueError("No extractable text (scanned PDF?)")
    return text

import re
def chunk_text(text: str, size: int = 800, overlap: int = 100) -> list[str]:
    paragraphs = [p.strip() for p in re.split(r"\n\s*\n", text) if p.strip()]
    chunks: list[str] = []
    current = ""
    for para in paragraphs:
        if len(current) + len(para) + 2 <= size:
            current = f"{current}\n\n{para}".strip()
            continue
        if current:
            chunks.append(current)
        tail = current[-overlap:] if (current and overlap) else ""

def pick_spread(chunks: list[str], n: int) -> list[str]:
    if len(chunks) <= n:
        return chunks
    step = len(chunks) / n
    return [chunks[int(i * step)] for i in range(n)]

class HybridRetriever:
    def __init__(self, chunks: list[str]):
        self.chunks = chunks
        vecs = _get_embedder().encode(chunks, normalize_embeddings=True)
        self.index = faiss.IndexFlatIP(vecs.shape[1])  # inner product = 
cosine (normalized)
        self.index.add(np.asarray(vecs, dtype="float32"))
        self.bm25 = BM25Okapi([c.lower().split() for c in chunks])
    def search(self, query: str, k: int = 5, rerank: bool = False) -> 
list[str]:
        pool = min(max(k * 3, 10), len(self.chunks))
        qv = _get_embedder().encode([query], normalize_embeddings=True)
        _, dense_ids = self.index.search(np.asarray(qv, dtype="float32"), 
pool)
        sparse_ids = np.argsort(self.bm25.get_scores(query.lower().split()))
[::-1][:pool]
        fused = rrf([list(dense_ids[0]), list(sparse_ids)])
        if not rerank:
            return [self.chunks[i] for i in fused[:k]]
        shortlist = fused[:pool]
        scores = _get_reranker().predict([(query, self.chunks[i]) for i in 
shortlist])
        order = np.argsort(scores)[::-1][:k]
        return [self.chunks[shortlist[i]] for i in order]

    return _norm(mcq.source_snippet) in _norm(chunk)
def validate(raw: dict, chunk: str) -> MCQ | None:
    try:
        mcq = MCQ(**raw)
    except (ValidationError, TypeError):
        return None
    return mcq if is_grounded(mcq, chunk) else None

def sha256_bytes(data: bytes) -> str:
    return hashlib.sha256(data).hexdigest()
def load_cache() -> dict | None:
    p = Path(settings.demo_quiz_path)
    return json.loads(p.read_text()) if p.exists() else None
def cached_quiz_for(data: bytes, n: int) -> list[MCQ] | None:
    cache = load_cache()
    if cache and cache["sha256"] == sha256_bytes(data):
        return [MCQ(**q) for q in cache["questions"]][:n]
    return None

7.1 Multi-stage Dockerfile kyun?
Ek Dockerfile mein 3 stage: base (runtime deps + models), test (base + pytest + tests),
runtime (base + non-root user). Jenkins test  stage pe pytest chalata hai, phir runtime
ko ship karta hai. Faayde: (1) test tools production image mein nahi jaate, (2) image chhoti,
(3) Trivy sirf us image ko scan karta hai jo actually deploy hogi, (4) wahi base layers pe
test hota hai jo ship hota hai.

8.5 Jenkins ke 4 gotchas (sab pe mera dhyan raha)
1. Volume mount trap: pipeline mein docker run -v $PWD:/src ...  mat likho. $PWD
Jenkins container ka path hai, wo host pe exist nahi karta, toh mount khaali aata hai. Isi
wajah se lint/tests image ke andar chalte hain, workspace mount nahi hota.
2. Jenkins image mein docker-compose-plugin  chahiye, warna docker compose
command nahi milega (upar ke Dockerfile mein hai).
3. Docker Hub free tier pe pull rate limit hai. Base images ek baar pull hone ke baad cache
mein rahenge.
4. Pehla build bahut slow hoga (torch + models). Doosra layer cache se aayega, isliye
pehle build ke liye samay rakho.
